01
The problem

Apps ship fixed screens.

Every screen is designed ahead of time, for the average user, for the cases we predicted.

The user adapts to the app: hunt the menu, learn the flow, fill the form we drew.

The interface is frozen at build time.

identical screens, every user, forever

The thesis

An assistant does three things an app can't.

What if the software reasoned about the request, acted on the real device, and generated whatever interface the moment needed?

Hold these three verbs — the whole talk hangs off them.

07
LangChain.dart

A Dart port of LangChain.

Unofficial Dart/Flutter port of the Python framework. Three core modules:

  • Model I/O — one API over many LLM providers.
  • Retrieval — loaders, embeddings, vector stores (RAG).
  • Agents — an LLM decides which tools to call. ← we live here.

Our Gemini entry point is ChatFirebaseVertexAI — so reasoning runs through the same Firebase project as rendering. One credential path.


// Stage 1 LLM — Gemini through Firebase
final llm = ChatFirebaseVertexAI(
  options: const ChatFirebaseVertexAIOptions(
    model: 'gemini-2.5-flash',
    temperature: 0, // determinism for the stage
  ),
);

No separate Google AI key — both stages = one Firebase project.

Stage 1 · the agent

The reasoning loop.


final tools = [
  queryTransactions,      // READ-ONLY
  summarizeSpending,
  setBudgetReminder,      // creates a calendar event
  updateBudgetReminder,   // edits it in place
];

final agent = ToolsAgent.fromLLMAndTools(
  llm: llm,
  tools: tools,
  memory: ConversationBufferMemory(returnMessages: true),
);

final executor = AgentExecutor(
  agent: agent,
  returnIntermediateSteps: true, // ← feeds the live trace panel
);

final result = await executor.invoke({'input': userText});
// result['output']            → final answer
// result['intermediateSteps'] → 🧠/🔧/✅ steps, rendered live

The intermediate steps ARE the hero visual — the audience watches it think.

Stage 1 · safety by design

The tool set is the boundary.

Beat 4 asks Aria to delete all transactions. It refuses — but not because of a prompt rule or a keyword filter.

It refuses because no delete tool exists. The capability was never registered.

Refusal is structural, not behavioural. You can't jailbreak a tool that isn't there.

11
genui

The model builds the UI.

A labs.flutter.dev package: the interface isn't predefined — the AI constructs it at runtime from a vocabulary you give it.

Core concepts:

  • Conversation — the facade & interaction loop.
  • Catalog / CatalogItem — widgets the AI may use.
  • SurfaceController — runtime UI engine.
  • DataModel — observable, data-bound state.
  • A2UI messages — createSurface / updateComponents…

// genui drives Gemini through onSend
_transport = A2uiTransportAdapter(
  onSend: _onSendToLLM,
);
_controller = SurfaceController(
  catalogs: [
    CoreCatalogItems.asCatalog()
      .copyWith(financeCards),
  ],
);
_conversation = Conversation(
  controller: _controller,
  transport: _transport,
);

genui · the moving parts

Six pillars of the SDK.

GenUiConversation
orchestrator — manages history and the interaction cycle.
ContentGenerator
model interface — connects to Gemini for text + UI generation.
A2uiMessageProcessor
command center — applies AI messages to DataModel + UI.
DataModel
dynamic state — observable store for all live UI data.
Catalog
widget toolkit — the native widgets the AI may render.
GenUiSurface
render zone — where the AI paints widgets on the fly.

In our build, Stage 1's AgentOutcome enters via ContentGenerator's prompt; everything below renders it.

Into the code · wiring genui

Processor → conversation.

genui's content generator runs Gemini through your existing Firebase project, with the catalog attached and the agent's outcome fed in as the prompt.

The A2uiMessageProcessor turns the model's A2UI messages into DataModel + surface updates; GenUiConversation orchestrates the loop and reports surfaces via onSurfaceAdded / onSurfaceDeleted.


final processor = A2uiMessageProcessor(
  catalogs: [foodCatalog],
);

final contentGenerator = FirebaseAiContentGenerator(
  catalog: catalog,
  systemInstruction: _renderSystemInstruction,
);

_conversation = GenUiConversation(
  a2uiMessageProcessor: processor,
  contentGenerator: contentGenerator,
  onSurfaceAdded: (e) => setState(() =>
    _surfaceIds.add(e.surfaceId)),
  onSurfaceDeleted: (e) => setState(() =>
    _surfaceIds.remove(e.surfaceId)),
);

Into the code · send & display

Send the outcome, render surfaces.


// Stage 1 finished → hand outcome to Stage 2
void _renderOutcome(AgentOutcome outcome) {
  if (_conversation
      .contentGenerator.isProcessing.value) return;
  unawaited(
    _conversation.sendRequest(
      UserMessage.text(outcome.toRenderPrompt()),
    ),
  );
}

The agent's structured outcome becomes the render prompt — the single bridge between stages.


// Each surface id → a GenUiSurface widget
ListView.builder(
  itemCount: _surfaceIds.length,
  itemBuilder: (context, i) => GenUiSurface(
    host: _conversation.host,
    surfaceId: _surfaceIds[i],
  ),
);

A tap inside a surface → new user turn → back through Stage 1.

16
The hard part

Two frameworks, one conversation.

Both want to own the model. LangChain's AgentExecutor drives Gemini through its reasoning loop. genui drives Gemini through its onSend transport to emit UI.

loop A

AgentExecutor → pick tool → run tool → feed back → repeat

loop B

onSend → stream chunks → A2UI messages → surfaces

If they interleave, they fight over the same model turn.

17
The rule that resolves it

Sequential, never overlapping.

stage 1 · reason

LangChain.dart

AgentExecutor runs to completion. Calls tools. Emits trace.

→

handoff

AgentOutcome

one structured object. The only bridge.

→

stage 2 · render

genui

Turns the outcome into surfaces. The model is never shared.

A tap inside a card (Confirm, toggle) doesn't re-enter Stage 2 directly — it becomes a new user turn through Stage 1. One direction, one owner at a time.

Lessons · shipping on alpha

How a live alpha demo survives.

Pin exact versions. genui moved 0.6 → 0.9 with breaking changes. genui: 0.9.0, no caret.
Build the deterministic path first. Mode 4A maps outcome → card in Dart (zero model variance) for beats 1–4. Mode 4B only for the finale.
Trust the installed code, not the docs. Verify the API against the package's own example/ folder — alpha docs drift.
Two young packages + a live model = variance. The fallback isn't polish; it's how you don't die on stage.

25
Honest tradeoffs

When to reach for generative UI.

good fit

  • Open-ended, hard-to-predict requests
  • Long-tail screens not worth hand-building
  • Assistive / conversational surfaces

keep it fixed

  • High-frequency core flows (checkout, login)
  • Anything needing pixel-exact consistency
  • Latency- or cost-sensitive paths

Generative UI is a layer on top of a real app — not a replacement for it.
